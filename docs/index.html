卖点靠什么实现你可以怎么检查

      
        

          不碰你的密码
          只接受只读的一次性凭证：微信读书的 API Key、QQ 邮箱的 IMAP 授权码。凭证存本机 ~/.selfloom/credentials.json，不进产物、不进日志、不进对话。

我是怎么验证它的

    
下面是开发过程中真实发生过的四次验证——包括我们自己的 bug。把过程摊开，比给一个"已测试"的标签更有说服力。

    

      

        
① 逐本对账微信读书的 249 本书

        
把接口声明的「划线 + 想法」与实抓记录逐本比对。发现 308 段划线在「划线」和「想法」里被各记了一次，属于 App 的重复计数，已合并。

        249 本书逐本差额 = 0
      

      

        
② 篡改计数，验证增量真的会重抓

        
手动把某一本书的 noteCount 改成 999，再跑一次同步。它精确重抓了那一本，其余 248 本走缓存。

        命中缓存 248 · 本次重抓 1 · 用时 2.1 秒
      

      

        
③ 抓到一个"程序不报错、结果却是空的"的 bug

        
DeepSeek 适配器最初把 99 场对话全部解析成 0 条记录，而程序报告"对账通过"——因为两边都是 0。根因是把"叶子节点"（自己没有子节点）写成了"不在任何子节点里"（即根节点）。

        已修，并新增硬规则：声明有数据却抓到 0 条 → 直接判失败
      

      

        
④ 一封 43 MB 附件的邮件，不再被反复下载

        
有封邮件正文为空、却带 43 MB 附件。原逻辑把它当"解析失败"，于是每次同步都重新下载 43 MB。修正为：「没有可导出的文本」是一个已归因的事实，不是错误——记录、计数、缓存，不再重下。

        16 封空正文邮件已归因 · 0 次重复下载
      

    

  






  

    
对账数据（一次真实运行）

    
这三行是这套工具的核心承诺：声明多少、抓到多少、差额去哪了。

    

      
平台来源声称实际抓到差额

      
        
微信读书2417 条（划线 + 想法）2417 条0

        
QQ 邮箱4257 封中命中 79 封79 封（66 封有条目 + 13 封空正文）0

差额为 0 的含义：每一笔"没导出"的东西都能说清去哪了（官方不提供内容 / 已归因的事实 / 你重新生成过的旧分支），没有一条是"不知道去哪了"。微信读书的 24 条书签属于第一类——官方只给数量、不给内容，我们在产物里如实标注。

    原理
    
为什么是这么设计的

    
每一个"不做"，都是想清楚之后才不做的。

    

      

        
1 为什么不要你的账号密码

        
因为"用密码换自动登录"这条路，技术上就走不通，而且在信任上是负收益。

        
微信读书的凭证来自微信扫码——微信根本不提供密码登录接口，硬做只能模拟点击，极易触发风控，代价是用户微信被封。QQ 邮箱的 IMAP 授权码生成时必须过短信验证，手机在用户手里，无法自动化。

        
所以凭证的获取无法自动化；但凭证的验证、保存、失效提醒完全可以——而那才是真正耗时的部分。这就是 auth（导入即校验）和 doctor（体检）存在的理由。

      

      

        
2 为什么必须有对账

        
这类工具最危险的失败不是报错，而是静默：程序正常退出、产物看起来完整，但实际上少了一半。

        
所以我们把两条规则写进产品：差额必须为 0 且逐项归因；来源有内容却抓到 0 条 —— 判失败。第二条在开发第一天就抓到了我们自己的 bug（见上面的检测③）。

      

      

        
3 为什么产物要分三层

        
因为"给 AI 读"和"给人查"是两种需求，混在一起两个都做不好。

        
机器层要一行一条、可流式、可检索；平台层要保留原生语义（微信读书按书/章，邮箱按日期）；汇总层要跨平台按时间混排。三者不是冗余，是三种用途。

      

      

        
4 为什么零第三方依赖

        
一个要接收你凭证的工具，多一个依赖就多一份供应链风险，也少一分可审计性。

        
所以 IMAP 客户端、MIME 解析、ZIP 读取、HTML 转文本，全部用 Node 内置模块手写。代价是开发慢一些，换来的是你能把全部代码读完，以及 npx 真正零安装。

我们不会假装拿到了没有拿到的东西

    
工具最该说清楚的不是它能做什么，而是它做不到什么。

    
    
      
  • 微信读书的书签：官方只提供数量、不提供内容。我们在产物里标注为「已归因的缺失」，而不是悄悄少给你。
    • 
      
  • QQ 邮箱的压缩包与内嵌图片：默认不落盘（有开关）。文档、PDF、PPT 这类会保留。
    • 
      
  • 豆瓣 / 知乎尚未支持。它们没有官方接口，需要浏览器自动化——稳定性和隐私成本都高得多，而且每次改版都可能失效。我们会在核心三平台稳定后再评估，不拿"即将支持"当卖点。
    • 
      
  • 任何平台只要出现「声明有数据、却一条都没抓到」，一律判为失败并报警，不会给你一份看起来成功的空结果。
    • 
      
  • 这是个人数据工具，请只导出你自己的账号数据。

    上手
    
三步跑出你自己的时间线

    
下面每一条命令都可以整段复制粘贴执行。只有标成 这种颜色的部分需要换成你自己的信息，其余一个字都不要改。


    

      
0 打开一个终端

      

        Windows：按 Win + R → 输入 powershell → 回车

        macOS：按 Command + 空格 → 输入 Terminal → 回车
      

      
⚠️ Windows 上请用 PowerShell，不要用 cmd 或「命令提示符」——cmd 会把命令里的尖括号当成重定向符号而报错。

    


    

      
1 先看效果（不需要任何凭证、不联网）

      npx selfloom demo
      
它用内置的虚构样例数据生成一份完整产物，让你先看清最终长什么样、值不值得接自己的数据。

    


    

      
2 接入你的平台（三个都可以接，也可以只接一个）


      
① 微信读书

      

        1. 浏览器打开 weread.qq.com/r/weread-skills 并登录

        2. 在页面「2 获取 API Key」那一栏，点「获取 API Key」按钮，再点出现的复制图标

        3. 回到终端运行下面这条（--clipboard 会自动读取你刚复制的 Key，不用手打）：
      

      npx selfloom auth weread --clipboard
      npx selfloom sync weread
      
不想用剪贴板？也可以手动粘：npx selfloom auth weread --key wrk-你的APIKey（--key 后面有一个空格，不要删）


      
② QQ 邮箱

      

        1. 浏览器打开 mail.qq.com 并登录

        2. 右上角头像 → 账号与安全 → 安全设置

        3. 找到「POP3/IMAP/SMTP/Exchange/CardDAV 服务」→ 点开启服务 → 按提示用手机发短信验证 → 复制生成的 16 位授权码

        4. 回到终端运行（把黄色部分换成你的真实邮箱，其余不要改）：
      

      npx selfloom auth qqmail --user 你的邮箱@qq.com --clipboard
      npx selfloom sync qqmail
      
授权码是 16 位字母，不是你的 QQ 密码。它只能收信、不能发信，随时可以在同一页面撤销。


      
③ DeepSeek

      

        1. 浏览器打开 chat.deepseek.com 并登录

        2. 左下角账号 → Setting → Data → Export data → 点下载

        3. 让 zip 留在默认的下载文件夹里（不用移动、不用解压），然后运行：
      

      npx selfloom sync deepseek
    


    

      
3 生成产物（三个平台通用，跑一次就够）

      npx selfloom export
      
产物写到 ~/.selfloom/out/，核心文件是 timeline.md。重复运行只更新、不会重复计算；没接入的平台不会出现在产物里。

日常更新很快——微信读书 1.5 秒、QQ 邮箱 0.6 秒，只处理有变化的部分。出问题时按右列处理。

常见问题

    
它会把我数据传到云端吗？
      
不会。它在本机运行，抓取结果写到 ~/.selfloom/，不做遥测。除了调用你授权的平台接口，它不与任何第三方通信。

    
需要科学上网吗？
      
不需要。它访问的都是国内可直连的接口（腾讯域名、QQ 邮箱 IMAP）。唯一需要梯子的场景是你在 GitHub 上下载源码。

    
我不会用命令行怎么办？
      
我们的目标是做成"解压一个文件夹、双击一个文件"。便携包正在做，会晚于命令行版本发布。如果你现在就想用，把 npx selfloom demo 这一行复制到终端回车，不会有任何副作用。

    
为什么先支持这三个平台？
      
因为它们都不需要浏览器。这带来三个直接好处：跨平台（Windows/macOS/Linux 通吃）、能无人值守、体积小。反过来，依赖浏览器自动化的平台（豆瓣、知乎）会让包的体积和失效频率都上去——那不该是一个早期产品的重心。

    
免费吗？
      
MIT 开源，完全免费，代码全部公开。如果你觉得有用，给个 star 就是最好的支持。

    
我的数据会不会被写进这个页面？
      
不会。页面上的示例内容来自内置的虚构样例数据；页面上出现的数字是容量统计（多少本书、多少封邮件），不含任何个人内容。
